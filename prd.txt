# PRD — PagePass: Read for Screen Time

## 1. Product Overview

**Product name:** PagePass
**App Store title:** PagePass: Read for Screen Time
**Tagline:** Read pages. Earn screen time.
**Positioning:** A reading-first parental control app that turns handwritten book reports into screen time.

PagePass는 아이가 종이책을 읽고, 손으로 독후감을 작성한 뒤 사진으로 제출하면, OCR 텍스트와 원본 사진을 부모가 확인하고 승인하는 앱이다. 승인되면 아이는 독서 시간에 비례한 screen time credit을 얻고, 본인이 명시적으로 Earned Time 세션을 시작해 부모가 정한 limited apps를 사용할 수 있다. OCR은 MVP 필수 review feature이고, AI는 부모 리뷰를 빠르게 돕는 보조 기능이다. 제품의 핵심은 **아이에게 사용 시작과 종료를 인지시키는 explicit wall-clock session으로 selected apps를 안정적으로 lock/unlock하고 경과시간을 차감하는 Screen Time control loop**다.

핵심 제품 루프:

```text
Read → Write by hand → Submit photo → Parent reviews → Earn screen time → Start Earned Time → Limited apps unlock
```

PagePass는 단순히 아이의 핸드폰을 막는 앱이 아니다. 목표는 **screen time을 협상 대상이 아니라 독서를 통해 얻는 보상으로 바꾸는 것**이다.

Core product rule:

```text
Credit = 0 → Limited Apps locked
Credit > 0, no active session → Limited Apps remain locked
Child starts Earned Time → Limited Apps unlock for the selected wall-clock duration
Child stops early → Apps lock and actual elapsed session time is deducted
Session expires → Apps lock and the selected duration is deducted
```

## 2. Core Idea

부모 입장에서는 아이에게 “핸드폰 그만해”라고 반복하는 대신, 명확한 규칙을 줄 수 있다.

```text
책을 읽고 독후감을 제출하면,
부모 승인 후 screen time을 얻는다.
```

아이 입장에서는 screen time을 빼앗기는 게 아니라, 직접 얻는 구조가 된다.

```text
I read. I wrote. I earned my time.
```

## 6. Technical Foundation

PagePass iOS app은 Apple Screen Time API 기반으로 동작한다. Apple의 Screen Time API suite는 **Family Controls, Managed Settings, Device Activity**로 구성되어 있으며, 앱 선택, 앱 shield, 예약된 interval 종료 콜백 같은 기능을 구현하는 데 사용된다.

Family Controls를 사용하는 앱은 배포 전에 Apple Developer Account Holder가 Family Controls entitlement 사용 허가를 요청해야 한다.

따라서 PagePass의 가장 큰 기술 리스크는 기능 구현 자체보다 **Family Controls entitlement 승인과 Device Activity interval callback 안정성**이다.

Physical validation status, 2026-07-17:

```text
iPhone XR / iOS 18.7.9
15-minute wall-clock schedule registration passed
Manual stop deducted only elapsed time and re-locked
Automatic expiry re-locked with the host app terminated
No DeviceActivityEvent or per-app usage measurement was used
```

## 7. Product Scope

## 7.1 MVP Goal

MVP의 목표는 아래 Screen Time control loop 하나를 안정적으로 완성하는 것이다.

```text
부모가 limited apps 설정
→ 아이가 reading timer 시작
→ reading mode 동안 limited apps lock
→ 아이가 손글씨 독후감 사진 제출
→ OCR text 생성
→ 부모가 원본 사진과 OCR text를 확인하고 승인
→ screen time credit 지급
→ 아이가 `Use Earned Time`을 누르고 사용할 시간을 선택
→ limited apps unlock
→ 아이가 직접 중지하면 실제 경과시간만 차감하고 즉시 lock
→ 선택 시간이 만료되면 자동 차감하고 lock
```

MVP success의 1순위는 **explicit session start/stop, scheduled expiry re-lock, elapsed-time settlement correctness**다. 이 로컬 control loop는 실기기에서 증명되었으며, 다음 과제는 부모 승인 credit과 자녀 기기 세션을 backend ledger로 연결하는 것이다. OCR은 MVP 필수 review feature다. AI는 이 루프와 OCR workflow가 동작한 뒤 붙이는 review assist 기능이다.

## 9. Key Product Concepts

## 9.1 Limited Apps

Limited Apps는 부모가 선택한 앱/카테고리/웹사이트 그룹이다.

예:

```text
YouTube
TikTok
Roblox
Instagram
Games category
Entertainment category
Safari or selected websites
```

이 앱들은 아이가 충분한 screen time credit을 가지고 있고 Earned Time 세션을 명시적으로 시작했을 때만 사용할 수 있다.

Product rule:

```text
No active Earned Time session → Limited Apps locked
Active Earned Time session → Earned Time apps unlocked
Blocked apps remain locked
Always Allowed apps remain open
```

## 9.2 Reading Mode

Reading Mode는 아이가 책을 읽는 동안 distracting apps를 막는 상태다.

Reading timer가 시작되면:

```text
Limited Apps shield ON
Reading session active
Child should read physical book
```

Reading Mode와 Earned Time 세션은 동시에 실행될 수 없다. 아이가 Earned Time 사용 중 독서를 시작하면 먼저 현재 세션을 중지하고 경과시간을 정산한 뒤 Reading Mode를 시작한다.

Reading timer가 끝나면:

```text
Book report photo required
Submission required before reward
No credit granted until parent approval
```

## 9.3 Handwritten Book Report

PagePass의 핵심 차별화는 독후감을 앱 안에 타이핑하지 않는 것이다.

아이는 종이에 손으로 쓴 뒤 사진을 찍어 제출한다.

이유:

* 폰 사용을 줄이는 제품 철학과 맞음
* 부모가 “진짜로 했다”는 신뢰를 얻음
* 단순 퀴즈보다 교육적 느낌이 강함
* App Store 마케팅 이미지가 명확함

## 9.4 OCR

OCR은 독후감 사진을 텍스트로 변환해 부모가 쉽게 읽을 수 있게 한다. OCR은 MVP 필수 기능이다.

Apple Vision framework는 이미지 속 텍스트를 인식하는 기능을 제공한다.

OCR은 필수 review feature지만 최종 판단 기준은 아니다. MVP에서는 OCR 결과를 “정답”으로 취급하지 않는다. 부모 화면에는 항상 원본 사진과 OCR 텍스트를 함께 보여준다.

UI copy:

```text
OCR may not be perfect. Please check the original photo.
```

## 9.5 AI Review

AI는 부모를 대체하지 않는다.
AI는 부모가 빠르게 판단하도록 도와준다.
AI는 core feature가 아니다. PagePass는 AI 없이도 reading reward와 Screen Time control loop가 동작해야 한다.

AI output:

* Summary
* Comprehension estimate
* Effort level
* Specificity
* Red flags
* Suggested parent questions
* Recommendation: Approve / Ask follow-up / Ask rewrite

Example:

```text
AI Review

Summary:
The child understood the main character’s problem and described one important event.

Comprehension:
Good for age 8.

Effort:
Medium. The report includes a personal opinion but could use more detail.

Suggested question:
Why do you think the character made that choice?

Recommendation:
Approve, but ask one follow-up question.
```

Final decision은 항상 부모가 한다.

## 9.6 Screen Time Credit

Screen time은 단순 balance number가 아니라 ledger로 관리한다.

Example:

```text
+40 min | Reading approved
-15 min | Earned Time session
-10 min | Earned Time session stopped early
```

Balance:

```text
Total earned - settled Earned Time sessions = current balance
```

Credit is stored in seconds internally and displayed as friendly hours and minutes. Every earn and spend mutation is an immutable, idempotent ledger entry.

## 9.7 Explicit Earned Time Session

PagePass는 credit이 생겼다는 이유만으로 limited apps를 자동으로 열지 않는다. 아이가 `Use Earned Time`을 눌러 사용 시작을 명확하게 인지해야 한다.

Duration choices:

```text
15 minutes
30 minutes, when balance allows
60 minutes, when balance allows
Use Maximum, meaning the full current balance
```

Session rules:

```text
Minimum startable session = 15 minutes
Selected duration cannot exceed the current balance
Balance below 15 minutes remains saved until more credit is earned
Starting a session unlocks only Earned Time apps
Manual stop locks first, then deducts ceil(actual elapsed seconds)
Automatic expiry locks and deducts the selected duration
Only one Earned Time session may be active per child
```

The child device registers a nonrepeating `DeviceActivitySchedule` with no `DeviceActivityEvent`. The system's `intervalDidEnd` callback re-applies the Shield even when the PagePass host app is not running. If delivery is delayed while the device is asleep, the host app reconciles the persisted deadline on its next launch or foreground transition.

The local session record is the enforcement source of truth until its idempotent settlement reaches the backend ledger. Duplicate callbacks or retries must not charge twice.

Offline rules:

```text
A child may start from credit already synced to the active child device.
Newly approved credit is not spendable until it reaches the child device.
Manual or automatic settlement locks locally first and queues backend sync.
Sync failure never reopens apps or restores locally consumed credit.
```

## 9.8 Session Notifications

실시간 초 단위 system countdown은 MVP에 필요 없다. PagePass가 열려 있을 때는 persisted deadline으로 남은 시간을 계산해 보여줄 수 있지만, backend나 앱 프로세스가 타이머를 계속 실행하지 않는다.

Child notifications:

```text
Time is up. Apps are locked.
```

Parent notifications:

```text
Book report submitted
Book report approved
Screen time finished, optional
```

Per-app usage milestones are not part of MVP because PagePass does not measure or deduct individual app usage. Dynamic Island / Live Activity는 나중에 polish 기능으로 추가한다.

## 9.9 App Requests And Persistent Parent Control

부모 기기의 `FamilyActivityPicker`가 자녀 앱을 정상적으로 표시하면 부모는 앱을 직접 등록하고 관리할 수 있다. 하지만 이 경로의 가용성과 별개로 자녀의 앱 요청 workflow를 항상 제공한다.

```text
새 앱은 기본 차단
→ 자녀가 앱 등록 요청
→ 부모에게 앱 이름과 아이콘 표시
→ 부모가 Blocked / Earned Time / Always Allowed 중 선택
→ 자녀 기기가 최신 부모 정책을 적용
```

App state rules:

```text
Pending        = requested but still blocked
Blocked        = always blocked
Earned Time    = unlocked only during an active Earned Time session
Always Allowed = always open and unaffected by Earned Time sessions
Unregistered   = blocked by default
```

자녀의 요청은 일회성 unlock이 아니라 부모의 지속 관리 목록에 앱을 등록하는 행위다. 한 번 등록된 앱은 부모 목록에 계속 남고, 부모는 자녀가 picker를 다시 열지 않아도 상태를 변경할 수 있다. 자녀는 요청을 만들 수 있지만 승인, 거절, 상태 변경, 정책 삭제는 할 수 없다.

Direct parent selection은 가능한 환경에서 제공하는 convenience path다. 자녀 요청 workflow는 부모 Picker가 비어 있는 환경에서도 동작해야 하는 독립적인 MVP path다.

## 10. User Flows

## 10.1 Parent Onboarding

1. Parent installs PagePass
2. Creates account
3. Creates child profile
4. Selects a child profile and opens `Connect Child Device`
5. Parent app displays a QR and 6-digit code for the same one-time pairing session
6. Child app scans the QR or enters the 6-digit fallback code
7. Backend binds that app installation to the selected child profile and issues a child-device-scoped credential
8. Child device requests `.child` Screen Time authorization
9. Parent/guardian approves Screen Time authorization
10. Parent configures the app policy through the chosen selection architecture
11. Parent sets reward rule
12. PagePass activates first policy

Default reward rule:

```text
1 minute reading = 1 minute screen time
Daily earn cap = 120 minutes
Minimum Earned Time session = 15 minutes
Carry-over = enabled
```

## 10.2 Child Reading Flow

1. Child opens PagePass
2. Taps `Start Reading`
3. Limited Apps lock
4. Child reads physical book
5. Child taps `Finish Reading`
6. App asks for book report photo
7. Child takes photo
8. OCR runs
9. Child reviews OCR preview
10. Child submits
11. Status becomes `Waiting for parent approval`

## 10.3 Parent Review Flow

1. Parent receives push notification
2. Opens submission
3. Sees:

   * Child name
   * Reading duration
   * Book title
   * Original photo
   * OCR text
   * AI Review, if available
4. Parent chooses:

   * Approve
   * Reject
   * Ask rewrite
5. If approved, credit is added

## 10.4 Earned Time Session Flow

1. Child has 0 credit
   → Limited Apps locked

2. Parent approves a report worth 45 minutes
   → Credit balance = 45
   → Limited Apps remain locked

3. Child taps `Use Earned Time`
   → Chooses 30 minutes or `Use Maximum`
   → Earned Time apps unlock

4. Child chooses 30 minutes and stops after 20 minutes
   → Apps lock immediately
   → 20 minutes are settled
   → Approx. 25 minutes remain

5. Child starts `Use Maximum`
   → The remaining balance becomes the session duration
   → At expiry, apps lock and balance reaches 0

6. If the child never starts another session
   → Credit remains saved
   → Earned Time apps remain locked

## 12. Technical Architecture

## 12.1 Recommended Architecture

```text
iOS App - Child Role
- SwiftUI
- SwiftData local cache
- FamilyControls
- ManagedSettings
- DeviceActivity
- Vision OCR
- UserNotifications

iOS App - Parent Role
- SwiftUI
- Parent review
- Policy management
- Credit ledger
- Push notifications

Backend
- Supabase or NestJS + PostgreSQL
- Object storage
- Optional AI analysis pipeline
- APNs push
```

## 12.2 Why Not SwiftData + Cloud Sync Only

SwiftData + iCloud sync is useful for syncing model data across one person’s Apple devices, but PagePass needs parent-child workflow, approval state, push notifications, credit ledger, audit logs, and optional AI analysis.

Therefore:

```text
Backend = source of truth
SwiftData = local cache and device enforcement state
```

## 12.3 Backend Responsibilities

Backend owns:

* Accounts
* Parent-child relationship
* Child profiles
* Child device registration
* One-time child-device pairing sessions
* Child policies
* Submissions
* Approval state
* OCR text
* Optional AI analysis
* Credit ledger
* Earned Time session settlement
* Push notifications
* Basic audit logs

## 12.4 Child Device Responsibilities

Child device owns local enforcement state, not product authority:

* FamilyActivitySelection tokens
* Local shield state
* DeviceActivity wall-clock session schedule
* Local active Earned Time session
* Idempotent pending session settlement queue
* Reading Mode state
* Local pending submission
* Local notification handling

Important:

```text
The backend should not rely on knowing exact app names.
Limited Apps authority remains parent-owned.
The child device keeps a local token vault and applies opaque Apple tokens only to enforce parent policy.
The child may register an app request but cannot classify, delete, or loosen its policy.
Direct parent selection is optional; the child-request workflow must work independently of the parent Picker.
```

Pairing rules:

```text

Successful pairing issues a device credential scoped to one child profile and app installation.
No parent credential, Apple ID, email, or child personal data is embedded in the QR.
The parent is notified when pairing succeeds and can revoke the device later.
```

## 14. Privacy and Safety

PagePass handles child data, handwritten photos, reading records, and Earned Time session records. Privacy must be treated as a core product feature, not a legal afterthought.

Apple’s App Review Guidelines state that Kids Category apps may not send personally identifiable information or device information to third parties and should not include third-party analytics or third-party advertising.

App privacy details must accurately disclose collected data and privacy practices.

MVP privacy rules:

```text
No ads
No third-party tracking
No selling data
No stealth monitoring
No message/content monitoring
No location tracking
Parent consent required
AI processing disclosed if AI Review is enabled
Original photos visible only to parent/child account
Delete data option required
Minimal child PII
```

AI safety rule:

```text
AI gives review assistance only.
AI does not make final approval decisions by default.
```

## 17. Recommended Build Plan

## Phase 0 — Explicit Earned Time Session Proof Gate

Status: passed on an iPhone XR running iOS 18.7.9 on 2026-07-17.

Goal: prove the core Screen Time mechanics on a physical child/teen Apple ID in Family Sharing without relying on per-app usage measurement.

Build:

* Family Controls entitlement request
* Apple Developer capability setup
* Physical test device setup
* Parent/child Apple ID Family Sharing test matrix
* `.child` authorization request on the child device
* Guardian approval flow
* ManagedSettings shield
* DeviceActivity nonrepeating schedule with zero usage events
* Explicit session start and unlock
* Manual stop with elapsed-time settlement
* Automatic interval expiry re-lock with the host app terminated
* Duplicate callback and recovery safety

Exit criteria:

```text
.child authorization succeeds on child device
guardian approval works
ManagedSettings can apply a shield
15-minute DeviceActivity schedule registers with zero events
Manual stop deducts only elapsed wall-clock time and re-locks
Automatic expiry applies the Shield with PagePass terminated
Duplicate callbacks do not double-charge
Registration failure preserves balance and remains locked
```

Observed platform constraint: a 5-minute schedule was rejected as too short on the tested device. MVP therefore requires at least 15 minutes of balance to start a session.

## Phase 1 — App Request And Persistent Parent Control Gate

Goal: prove that one child request creates a durable parent-managed app item and that the parent can repeatedly change its policy without another child picker action.

Build Gate A first:

* Child requests exactly one app through the child-device picker
* Manual child-to-parent request envelope transfer
* Parent renders the app name and icon
* Manual parent-to-child policy envelope transfer
* Default-block shield policy with explicit exceptions
* Mandatory Safari token enrollment because category-wide shielding excludes
  Safari by design
* Safari bundle-ID blocking as the fail-safe before enrollment and whenever a
  valid Safari token is unavailable

Build Gate B only after Gate A passes:

* QR and 6-digit pairing
* Scoped child-device credential
* Idempotent app request API
* Parent-only policy decision API
* Versioned child policy fetch and applied acknowledgement
* Multiple-child isolation

Exit criteria:

```text
Pending and Blocked remain shielded
Earned Time apps unlock only during an active Earned Time session
Always Allowed remains open regardless of session state
Unregistered and newly installed shieldable apps remain blocked
Parent policy persists and the child cannot mutate it
```

The full test procedure is defined in `docs/superpowers/specs/2026-07-14-child-app-request-parent-control-spike-design.md`.

## Phase 2 — Nx Foundation

Goal: create the smallest monorepo that can support the proven native loop.

Build:

* `apps/api`
* `apps/mobile-ios`
* `libs/shared`
* XcodeGen `project.yml` for reproducible native target generation
* `nx run mobile-ios:build` wrapper around `xcodebuild`

The product app is created fresh under `apps/mobile-ios`; the existing Screen
Time spike remains separate validation evidence. Only proven wall-clock session,
Shield, monitor-extension, and App Group transaction behavior is ported.

Exit criteria:

```text
nx run api:build
nx run shared:build
nx run mobile-ios:build
```

## 24. Final Decision

Build PagePass as a **parent-controlled iOS app with child-device enforcement and a thin backend**.

```text
Parent app owns rules, review, approval, and child-specific policy.
Backend owns policy versions, approvals, credit ledger, audit logs, optional AI analysis, and notifications.
Child iPhone enforces the parent policy and active Earned Time session locally through Screen Time APIs.
```

This architecture gives the best balance between iOS system limitations, App Store safety, product reliability, and launch speed.
